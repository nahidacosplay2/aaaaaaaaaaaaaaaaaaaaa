# Zapret Aris для Android

Экспериментальное Android-приложение с двумя маршрутами трафика и отдельным прокси для Telegram. Root не требуется. Эффективность зависит от провайдера и конкретной сети; универсальный обход не гарантируется.

- **Zapret:** локальный VPN направляет трафик через ByeDPI/HEV на телефоне. Внешний SOCKS-сервер не используется.
- **SOCKS5:** Android VPN направляет трафик через настроенный SOCKS5-сервер. Можно указать адрес, порт и учётные данные; для UDP сервер должен поддерживать `UDP ASSOCIATE`. Настройки принимают SOCKS5 endpoint, а не ссылки VLESS/VMess. Xray можно использовать, если он предоставляет SOCKS inbound.
- **Прокси Telegram:** отдельная дополнительная функция; она не заменяет ни один из двух маршрутов.

**Статус:** в репозитории пока нет готового APK или публичного релиза. Android-сборка, VPN-маршрутизация, DNS и UDP на устройстве ещё не проверены. Кнопка теста SOCKS5 проверяет TCP handshake и тестовое TCP-соединение; сама по себе она не подтверждает работу UDP, DNS или системного VPN-туннеля.

Исходная кодовая база основана на [Zapret Cap для Linux](https://github.com/CapptainnCWC/zapret-cap). В проекте также используются стратегии [zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube), [zapret2](https://github.com/bol-van/zapret2) от bol-van, прокси для Telegram [tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy), ByeDPI и HEV. Лицензии перечислены в [THIRD_PARTY.md](THIRD_PARTY.md).

## Режимы работы

В режиме **Zapret** выберите стратегию для Wi-Fi или мобильной сети и запустите маршрут. Стратегии и доменные списки основаны на исходном проекте; результаты могут отличаться на разных сетях. Отключайте другие VPN перед запуском: Android разрешает одновременно только один VPN-сервис.

В режиме **SOCKS5** задайте сервер и порт. При первом выборе SOCKS5 приложение откроет форму настройки; после сохранения режим выберется автоматически. Логин и пароль необязательны, но если сервер требует аутентификацию, укажите оба поля. Сам протокол SOCKS5 не шифрует трафик или учётные данные: используйте только доверенный сервер и сеть. По желанию можно исключить из VPN установленное приложение с локальным SOCKS-сервером; для обычного удалённого сервера это поле оставляют пустым. Успешная TCP-проверка не подтверждает UDP-трафик или работу всех приложений.

## Как пользоваться

1. В переключателе маршрутов выберите **Zapret** для локального ByeDPI или **SOCKS5** для настроенного прокси-сервера.
2. Нажмите **Запустить маршрут**. Android спросит разрешение на VPN; разрешите его, чтобы выбранный маршрут запустился.
3. В режиме Zapret проверьте нужный сайт. Если он не открылся, нажмите **Подобрать** или выберите другую стратегию. Проверка и выбор стратегий недоступны в режиме SOCKS5.

Конфиг выбирается отдельно для мобильной сети и для каждой Wi-Fi сети: у разных провайдеров и роутеров рабочие конфиги разные. Вкладки над списком показывают выбор для Wi-Fi и мобильной сети, а под ними написано, в какой Wi-Fi сети телефон сейчас. При переходе на другой Wi-Fi обход сам включает конфиг этой сети, итоги **Подобрать** и подобранный TTL тоже хранятся для каждой сети. В новой сети сначала стоит последний выбор для Wi-Fi.

Wi-Fi сети различаются по имени. Android сообщает имя сети только приложениям с доступом к местоположению, поэтому под вкладками есть кнопка **Различать Wi-Fi сети по имени**. Чтобы обход переключался и при закрытом приложении, выберите доступ **Разрешить всегда**, геолокация должна быть включена. Само местоположение приложение не запрашивает и никуда не отправляет. Без доступа сети различаются по адресам роутера, а у большинства роутеров они одинаковые, поэтому такие сети будут считаться одной.

Подходящий конфиг зависит от провайдера, а со временем рабочий может перестать помогать. Это нормально: снова нажмите **Подобрать**.

**Подобрать** заменяет тест конфигураций из Windows-версии. Приложение по очереди открывает через каждый конфиг Discord, YouTube, Cloudflare, поисковики и сайты, которые вы добавили сами, и показывает, сколько открылось. Сразу за этим каждый конфиг проверяется на замирание на 16-20 КБ, как DPI-тест Linux- и Windows-версий: на 36 серверов разных хостингов из набора [dpi-checkers](https://github.com/hyperion-cs/dpi-checkers) отправляется по 64 КБ по HTTP, TLS 1.2 и TLS 1.3. Если данные ушли, а ответа нет до таймаута, это фриз: так провайдер останавливает соединения с зарубежными хостингами. На время этой проверки IPSet работает как **Все адреса**. В списке конфигов видно и число открытых сайтов, и число фризов. Сначала сравниваются сайты, при равенстве побеждает конфиг с меньшим числом фризов. В мобильной сети проверка фризов облегчённая, по одному серверу на хостинг и только TLS 1.3: полная отправляет около 7 МБ на каждый конфиг. Полностью убрать такие фризы, как в Linux- и Windows-версиях, без root не получится: там обманка идёт с неверным номером TCP-пакета и сбивает провайдеру счёт байтов, а приложение без root может испортить обманку только малым TTL, и счёт при этом не сбивается. Подмена через подпись MD5 тоже не поможет: ядра Android собраны без неё. Лучшие конфиги проверяются ещё раз, в счёт идёт худший результат. Конфиг, который ломает поисковики, не победит. Проверка занимает несколько минут, разрешение на VPN для неё не нужно. Экран в это время не гаснет. Если даже лучшие конфиги открыли не всё или на них есть фризы, приложение пробует другой TTL фейков и запоминает его для этой сети.

## Какие сайты обрабатываются

В режиме Zapret кнопка **Домены** открывает три списка. Эти списки и стратегии не управляют трафиком, который идёт через внешний SOCKS5-маршрут.

- **Обход:** к этим сайтам и их поддоменам применяется обход: Discord, Cloudflare, WhatsApp, Instagram и другие. Сюда добавляйте сайт, который не открывается.
- **YouTube:** домены YouTube и Google, у многих конфигов для них свои приёмы.
- **Не трогать:** эти сайты идут без изменений. Сюда уже входят крупные российские сервисы (Госуслуги, банки, маркетплейсы, магазины, операторы связи, VK, MAX, Яндекс, СМИ) и каналы пуш-уведомлений: они не заблокированы, и обход им только мешает. Сюда добавляйте сайт, который без обхода работает, а с ним ломается.

Введите домен или вставьте адрес сайта и нажмите **+**: `https://`, `www` и путь уберутся сами. Можно вставить несколько доменов через запятую. То же поле ищет по списку. Домен находится только в одном списке: если добавить его в другой, из прежнего он уберётся. **Вернуть исходный список** отменяет ваши изменения в разделе. Изменения применяются при возврате на главный экран.

## Настройки обхода

Кнопка **Настройки обхода** внизу главного экрана. Это те функции `service.bat` из Windows-версии, которые имеют смысл на телефоне и работают без прав root.

| В приложении | В `service.bat` | Что делает |
| :--- | :--- | :--- |
| **Обход по IP-адресам (IPSet)** | IPSet Filter | **Выключен:** обход только для доменов из списков. **По списку:** ещё и для подсетей из списка zapret-discord-youtube. **Все адреса:** для всех сайтов, кроме «Не трогать» |
| **Обновить** список IPSet | Update IPSet List | Загружает свежий список подсетей с GitHub проекта |
| **Фейк для голоса Discord** | Replace active fakes | Какой пакет-обманка идёт перед голосовыми соединениями Discord |
| **Адреса из hosts** | Update Hosts File | Для Telegram, Discord и GitHub приложение отвечает адресами из списка проекта. Системный файл hosts не меняется, адреса подставляет DNS приложения |

Фильтр игр из Windows-версии не перенесён: он нужен для игр через Steam. Изменения применяются при возврате на главный экран.

Ещё там есть **TTL обманок**, отдельно для Wi-Fi и мобильной сети. В Windows-версии такой настройки нет: там обманки портятся иначе. Без root обманка работает только за счёт малого TTL: она должна дойти до оборудования провайдера, но не до сайта, а расстояние до того и другого зависит от сети. Конфиги `general` используют TTL 8, `vpn combo` 5 и 6. **Авто** оставляет TTL из конфига и то, что нашёл **Подобрать**. Число задаёт TTL для всех обманок любого конфига в этой сети, и **Подобрать** тогда проверяет конфиги с ним.

- С обходом перестали грузиться сайты или приложения, которые работают и без него: TTL велик, уменьшите. Например, на одной из проверенных Wi-Fi-сетей конфиги `general` с TTL 8 ломали загрузку настроек с GitHub у приложения AniLibria, а с TTL 6 всё работало.
- Заблокированный сайт не открывается и с обходом: TTL мал, увеличьте.

## DNS

В режиме **Zapret** DNS-запросы обслуживает DNS-компонент приложения: он использует DoH Cloudflare/Google и резервные DNS, в том числе DNS текущей сети, и применяет настроенные списки. В режиме **SOCKS5** HEV создаёт локальные IPv4-адреса DNS-ответов, а дальнейшее разрешение имени зависит от SOCKS5-сервера. Это поведение ещё не проверено end-to-end; поддержка AAAA/IPv6 DNS может отличаться.

## Белые списки на мобильном интернете

Иногда оператор оставляет доступ только к разрешённым сайтам, остальные адреса не отвечают вообще, даже без обхода. Локальный режим Zapret не снимает такую IP-блокировку. В SOCKS5-режиме сам прокси-сервер тоже должен быть доступен из этой сети, иначе соединение не установится. Проверяйте правила оператора и законность использования прокси в вашей сети.

Туннель работает внутри приложения: если прошивка его заморозит, через VPN не пройдёт ни один пакет, а уведомления будут приходить только после включения экрана. Поэтому приложение проверяет оптимизацию батареи, ограничение фоновой работы и автозапуск. Если что-то мешает, наверху главного экрана появится карточка **Фоновая работа**, а при включении обхода уведомление с кнопками в нужный раздел настроек.

- **Xiaomi:** автозапуск приложение проверяет само, а **Контроль активности → Нет ограничений** проверить не может: выберите его и нажмите **Уже настроил**.
- **Huawei и Honor:** **Батарея → Запуск приложений → Zapret Aris**, выключите автоматическое управление и включите все три переключателя. Без этого телефон с выключенным экраном держит приложение замороженным, и уведомления не приходят часами.
- **Samsung:** уберите Zapret Aris из спящих приложений.

Чтобы обход включался сам вместе с телефоном, откройте в настройках Android раздел **Сеть и интернет → VPN → Zapret Aris** и включите **Постоянная VPN**. Название раздела зависит от телефона.

## Прокси для Telegram

Отдельная функция для случаев, когда Telegram не подключается или плохо грузит фото и видео. Она запускается независимо от основного маршрута Zapret/SOCKS5. Основа: [tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy).

1. Включите переключатель **Прокси Telegram**.
2. Нажмите **Подключить в Telegram**. Откроется Telegram и спросит, добавить ли прокси: согласитесь.

Это отдельная служба, не связанная с выбранным маршрутом Zapret/SOCKS5. Она работает в фоне и показывает собственное уведомление.

При первом включении Android спросит, можно ли приложению работать в фоне без ограничений. Разрешите: иначе экономия батареи может усыплять прокси, и Telegram будет переподключаться.

Telegram запоминает этот прокси. Если выключить его только здесь, Telegram перестанет подключаться. Чтобы отказаться от прокси, сначала отключите его в самом Telegram: **Настройки → Данные и память → Настройки прокси**.

Если приложение пишет «Telegram не найден», ссылка уже скопирована: отправьте её себе в «Избранное» и нажмите на неё в Telegram. Можно добавить прокси и вручную, тип MTProto: сервер `127.0.0.1`, порт `1443`, ключ `dd` и затем ключ из настроек.

### Куда идут данные

Телефон подключается к серверам Telegram через WebSocket, а там, где это не работает, через домены на Cloudflare. Эти домены обслуживают другие люди: переписка остаётся зашифрованной протоколом Telegram, но владелец домена может видеть ваш IP-адрес и объём трафика. Свой домен можно указать в настройках: [CF-прокси](https://github.com/Flowseal/tg-ws-proxy/blob/main/docs/RU/CfProxy.md) или бесплатный [Cloudflare Worker](https://github.com/Flowseal/tg-ws-proxy/blob/main/docs/RU/CfWorker.md).

Список доменов приложение раз в час обновляет с GitHub проекта tg-ws-proxy.

### Обход для прокси

Прокси не зависит от основного обхода, как tg-ws-proxy на компьютере: конфиг, хороший для YouTube, бывает плох для Telegram. Конфиг для прокси выбирается строкой **Обход для прокси** в карточке Telegram на главном экране (тот же пункт есть в **Настройках** прокси):

- **Без обхода** (по умолчанию): прокси соединяется с Telegram и Cloudflare напрямую.
- **Конфиг из списка:** для прокси запускается отдельный движок с этим конфигом. Основной обход при этом может быть включён с другим конфигом или выключен.

### Если Telegram работает плохо

**Постоянно переподключается.**
- Проверьте, что экономия батареи не ограничивает приложение: **Настройки Android → Приложения → Zapret Aris → Батарея → Без ограничений**. На Xiaomi, Huawei, Samsung и похожих телефонах название раздела может отличаться, там же может быть отдельная настройка автозапуска.
- Если обход включён, выключите его и проверьте без него. Если стало лучше, нажмите **Подобрать**.
- Если не помогло, откройте **Настройки → Журнал**, нажмите **Скопировать** и пришлите текст разработчику. В журнале видно, какой маршрут оборвался и кто закрыл соединение. Если приложение падало, там же будет причина сбоя.

**Не грузятся фото и видео.** Откройте **Настройки** и в поле «Датацентры Telegram» оставьте только `4:149.154.167.220`. Если не поможет, очистите поле полностью и нажмите **Сохранить**.

**Не подключается вообще.** В настройках нажмите **Проверить**: приложение покажет, какие маршруты отвечают. Если обход включён, попробуйте другой конфиг. Подробности есть в разделе **Журнал**.

**Пишет, что порт занят.** Порт уже использует другое приложение. Укажите в настройках другой порт и снова нажмите **Подключить в Telegram**: Telegram должен узнать новый адрес.

## Чем отличается от Windows-версии

Приложению не нужны права root: всё работает через локальный VPN.

### Почему стратегии только близкие

Без root Android не разрешает приложениям отправлять собственные сетевые пакеты, поэтому часть приёмов из Windows-версии здесь невозможна.

- **Остаётся таким же:** фейки QUIC и Discord, разбиение TLS на те же позиции, списки сайтов.
- **Заменяется:** фейки с подделанными `ts` и `badseq` и приём `seqovl` становятся фейками с малым TTL. Такой пакет видит оборудование провайдера, но он не доходит до сайта.
- **Пропадает:** `syndata`. В конфиге ALT5 остаётся только изменение порядка сегментов.

Поэтому конфиг, рабочий в Windows, не обязательно заработает здесь, и наоборот. Подробное сравнение: [docs/PORTING.md](docs/PORTING.md).

В конце списка есть дополнительные конфиги ByeDPI. Для новой установки по умолчанию предлагается **vpn auto**; это только стартовый выбор, а не гарантия, что он подойдёт вашей сети. **vpn auto** пробует следующий приём при сбросе соединения; **vpn disorder**, **vpn split**, **vpn tlsrec** и **vpn oob** обходятся без TCP-фейков. Результат зависит от сети — при необходимости запустите **Подобрать**.

## Если что-то не работает

**Сайт перестал открываться у всего телефона.** Нажмите **Выключить**. Если стало лучше, причина в конфиге: выберите другой.

**Открываются не все сайты.** Обход применяется только к сайтам из списка. Добавьте нужный сайт через кнопку **Домены**.

**Сайт работает без обхода, а с обходом нет.** Добавьте его в список **Не трогать** через кнопку **Домены**.

**На мобильном интернете открываются только российские сайты.** Скорее всего, оператор включил белые списки, см. раздел выше. Проверить просто: выключите обход. Если заблокированные сайты всё равно не открываются, причина не в приложении.

**Ни один конфиг не помогает.**
- Нажмите **Подобрать**, если ещё не пробовали: там видно, сколько сайтов открывается с каждым конфигом и без обхода.
- Выключите другие VPN и программы для обхода блокировок: одновременно на телефоне может работать только один VPN.
- Попробуйте **Настройки обхода → IPSet: По списку**: обход будет работать и для адресов из списка подсетей, а не только для доменов.
- Проверьте другую сеть: мобильный интернет и домашний Wi-Fi часто блокируются по-разному.

**С включённым маршрутом не приходят уведомления приложений.** Туннель настроен сохранять длительные TCP-соединения, но поведение уведомлений не проверено на устройстве. Проверьте, не ограничивает ли прошивка фоновую работу приложения и службы push-уведомлений; названия разделов зависят от производителя.

**Сайты начинают грузиться и застывают, файлы не скачиваются.** Если включён **IPSet: По списку**, выключите его. В списке подсетей есть Cloudflare, и там, где провайдер не замедляет Cloudflare сам, обманка у его адресов может замораживать соединение после первых ~20 КБ: страницы открываются, а загрузки стоят. На одной из проверенных Wi-Fi-сетей так вели себя все варианты обманки, без обманки загрузка шла на полной скорости. **Подобрать** проверяет и такую загрузку с Cloudflare.

**Сайт или приложение перестали грузиться только при включённом конфиге с фейком.** Сервер может находиться слишком близко, тогда пакет с малым TTL доходит до него и ломает соединение. Уменьшите **TTL обманок** в **Настройках обхода** или попробуйте **vpn disorder** и ALT5: в них нет фейков для TCP.

## Сборка и проверка

Нужны JDK 17, Android SDK 35 и NDK `28.2.13676358`. Путь к SDK укажите в `local.properties`:

```text
sdk.dir=/путь/к/Android/Sdk
```

Соберите debug APK из этой папки:

```bash
./gradlew assembleDebug
```

Файл должен появиться в `app/build/outputs/apk/debug/`. Workflow [.github/workflows/android-apk.yml](../.github/workflows/android-apk.yml) собирает release-вариант для проверки и прикладывает APK с SHA-256 к запуску Actions на 14 дней. Без release-keystore этот CI APK подписан временным debug-ключом и годится только для тестовой установки: его нельзя использовать для стабильных обновлений или публикации в Google Play. Успешная сборка ещё не означает проверку на устройстве; для публичного релиза необходимы постоянный release-ключ и тесты на реальных сетях. Автоматических обновлений в приложении нет.

На Linux можно выполнить вспомогательный host-side тест стратегий без root, если установлены `gcc`, `iproute2`, `nftables`, `openssl`, `curl`, `python3` и разрешены user namespaces:

```bash
tests/vpn-sandbox-test.sh
```

Старый вывод sandbox-теста перечислял `vpn split`, `vpn disorder`, `vpn auto`, `vpn oob` и `vpn tlsrec` как прошедшие, а `vpn combo`, `vpn fake` и `general` как ошибочные. При повторной проверке обнаружено, что в той среде отсутствовал `nft`, поэтому обязательное правило фильтрации TTL не применилось и эти результаты недостоверны, особенно для стратегий с фейками. Тестовый скрипт теперь проверяет `nft` и прекращает запуск с кодом 77; в текущей среде suite пропущен именно по этой причине. Нужен повторный запуск на Linux с `nftables`. Это не Android/device-тест. SOCKS5 TCP-проба также не проверяет UDP, DNS или реальную маршрутизацию через Android VPN.

Тесты прокси Telegram запускаются командой `tests/tgproxy-test.sh unit`. Скрипты в `tests/phone/` предназначены для проверки по adb на реальном телефоне; команды управления VPN-движком есть только в debug-сборке.

Без `keystore.properties` debug APK подписывается отладочным ключом. Для последующих установок поверх той же сборки используется тот же application ID и ключ подписи; для релизов нужен отдельный ключ, который следует хранить вне репозитория.

| Что | Где |
| :--- | :--- |
| Приложение | `app/src/main/java/app/zapret/aris/` |
| Прокси Telegram | `app/src/main/java/org/zapretcap/tgproxy/` |
| Конфиги | `app/src/main/assets/strategies/` |
| Перевод стратегий с Windows | `tools/bat2conf.py`, `tools/bat2vpn.py` |
| Сборка движков | `native/build-native.sh` |
| Проверки | `tests/` |
| Проверки на настоящем телефоне | `tests/phone/` |
