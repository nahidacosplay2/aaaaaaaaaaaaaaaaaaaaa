# Zapret Aris — проверка текущих файлов и план развития

Дата проверки: 2026-11-19.

## Что реально загружено

- `ZapretAndroid-v1.10.4-r3.apk` — Android-пакет размером 8,827,771 байт.
- `ZapretAndroid-v1.10.4-r3.zip` — те же файлы пакета: общие файлы совпадают побайтно; ZIP дополнительно содержит записи каталогов. Это не исходный проект.
- В APK видны Android `VpnService`, `libbyedpi.so`, `libhev-socks5-tunnel.so`, данные Flowseal v1.10.4, списки целей, TLS/QUIC/UDP-ресурсы и SOCKS5-строки. Это анализ содержимого, не полевой тест: из него нельзя заключить, что конкретный профиль сейчас проходит фильтрацию у любого оператора.
- `index.html` — новая Arisu-панель для демонстрации интерфейса. Она не запускает TUN, Xray или прокси-движок.

### Честное сравнение

По текущей реальной сетевой функциональности загруженный APK впереди: у него есть нативные компоненты, а Arisu-панель пока только прототип интерфейса. По новому оформлению и более простому выбору профиля/транспорта впереди прототип. Называть его «лучшим рабочим APK» было бы неверно.

## Что следует из upstream-проектов

- [Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube) хранит версии стратегий и списков отдельно и предлагает проверять конфигурации тестами. Для мобильной версии это аргумент за версионированные профили и тестируемый fallback, а не за случайное включение всех переключателей сразу.
- [bol-van/zapret](https://github.com/bol-van/zapret) — отдельный DPI-инструментарий; его профильные параметры нельзя считать универсальными для всех сетей, операторов и типов блокировки.
- [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) описывает локальный MTProto-прокси для Telegram через WebSocket. Его нужно показывать как отдельный Telegram-сценарий, а не обещать, что он перенаправит трафик всех приложений.
- [XTLS/Xray-core](https://github.com/XTLS/Xray-core) — отдельное прокси-ядро. Это не ещё один профиль Flowseal: конфигурации VLESS/VMess/Trojan требуют работающего Xray-совместимого ядра. Поле SOCKS5 в Arisu может указывать на уже поднятый локальный SOCKS5-вход, но само по себе Xray не запускает.

## Приоритеты для действительно работающего APK

### P0 — получить исходники и воспроизводимую сборку

Нужен исходный Android-проект вместе с Kotlin/Compose-кодом, Gradle-файлами, JNI/NDK/Rust-частями и лицензиями. Сейчас в репозитории только APK и его файловая копия в ZIP; безопасно встроить новый интерфейс и пересобрать именно этот APK из этих двух бинарников нельзя.

### P1 — тестировать причину сбоя, не «весь интернет» одним переключателем

Сделать нативную диагностику по этапам: DNS-разрешение, TCP-доступность, TLS-рукопожатие, UDP/443 и доступность выбранного прокси. Отдельно показывать timeout, отказ DNS и сброс соединения. Результат привязывать к профилю, типу сети и времени; не отправлять домены и адреса пользователя без явного согласия.

### P2 — один владелец VPN-маршрута на Android

У Android-VPN приложение получает системный TUN-маршрут. Второе VPN-приложение обычно не может просто «встать поверх» первого. Для Xray нужно выбрать один реальный вариант: интегрировать совместимое ядро в тот же VPN-сервис или направлять трафик через локальный SOCKS5-вход, который уже поднял Xray. Не показывать VLESS-ссылку как SOCKS5-адрес и не обещать совместную работу, пока это не проверено на устройстве.

### P3 — разделить стратегии и не ломать прокси-туннели

Поток напрямую к сайту, внешний Xray-туннель и Telegram WebSocket — разные маршруты. Тестировать их раздельно; не применять произвольные TCP/TLS/QUIC-параметры Flowseal к внешнему зашифрованному соединению Xray без проверки. Для каждого профиля хранить известный рабочий вариант и понятный ручной fallback; любые обновления списков привязывать к версии и контрольной сумме.

### P4 — сеть, DNS и утечки

Добавить профили Wi-Fi/мобильной сети, явный выбор DNS, IPv4/IPv6 и UDP-поведения, выбор приложений, MTU-диагностику и проверку того, что DNS/IPv6 не идут мимо выбранного маршрута. Перед включением блокировки трафика показать, что будет происходить при падении туннеля; не переключать пользователя на более открытый маршрут незаметно.

### P5 — релиз и доверие

Публиковать APK в GitHub Releases с номером версии, SHA-256, исходным commit, подписью релиза и понятной пометкой, какие ядра/списки вошли в сборку. Не подменять этим исходный APK и не выдавать UI-прототип за новый бинарник.
